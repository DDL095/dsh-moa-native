# Changelog

## 4.5.1 (2026-11-07)

The compatibility release: one build runs on both DSH 0.2.1 and 0.2.2 lines, and the trimmed (R) mode gets a wider window.

- **Default mode is F (full mirror) — and it is the expensive one. Read this before sizing a lineup.** Every reference route receives the exact system prompt, tool definitions, and full history the acting model sees: zero information asymmetry, KV-cache-friendly (hit rates above 90% with guidance anchoring), but the input bill scales with the conversation length on every beat. The console's *recommended mode* (F + blank-injection flash refs + tiered cadence) is tuned to keep that bill low — flash refs, frozen reuse between beats, anchored guidance. If your sessions run long and the input cost still hurts, switch a recipe to **R** — that is what it exists for.
- **R (trimmed view, the Hermes-lineage mode) gets a wider window**: the per-tool-result truncation budget doubles 4,000 → 8,000 chars, and the overall refs-view budget widens 120,000 → 160,000 chars (≈40–80k tokens). Both are now configurable per install — `ref_tool_result_budget` and `ref_input_char_budget` (global top-level keys; R only, F full mirror is unaffected). Tighten them back for small-window refs, widen further for 1M-context routes. R still drops the system prompt and folds tool results by design — it is the economy lane, not a second mirror.
- **Cross-version dual-track routing (host compatibility)**: one build now serves both the 0.2.1 line and the 0.2.2-rc line of the DSH host — the interceptor detects which routing surface the host exposes (`agent.model.select` vs rewrite) and rides it; no config change needed across host upgrades. Verified on a sandbox preview before the production swap, then on production itself after the swap.
- **`webServer` moved from module-level injection to runtime lazy attach**: plugin load no longer touches the host web server at import time — fixes activation-order fragility observed on the 0.2.2-rc line (a cold host could expose the panel routes before the server object existed).
- Housekeeping: pinned-version assertions in the older verify matrices (`verify-v28`/`verify-v4312`, with `verify-v29` reading the pin) are updated with this bump — they were left pointing at 4.4.0 when 4.5.0 shipped and went red as a result.

## 4.5.0 (2026-11-05)

The cache-friendly release: guidance is pinned where it was produced, and the memory anchor no longer rewrites the system prompt.

- **Guidance pinned at the beat (the core change)**: the aggregator's rehearsal record used to be appended to the *end* of every request. Provider caches match on the longest common prefix, so a trailing record is never in the same position twice — the cached prefix only reached the beat history, and the rehearsal record was re-billed on every step. It is now pinned immediately after the message that produced it, so `[beat history][rehearsal]` stays byte-identical across the frozen steps: the whole segment hits the cache and each step pays only for what was added since. The anchor is located by **message id**, never by index (a surface `replace` moves indices). The anchor travels **with the cache entry** — it is recorded on a real fan-out and read back on a frozen reuse; deriving it from the current tail would drift and degenerate into the old trailing form.
- **Applies to every cadence**: the injection sits outside the fresh/frozen branch, so `user_turn`, `per_iteration`, `every_n`, and `tiered` all benefit. Measured on frozen steps (trace-aligned): trailing era 3,308 uncached tokens on average → pinned era 1,931 (same session, −36%); hit rate p50 99.15%.
- **On by default**: `guidance_anchor` defaults to **on**; only an explicit `false` returns to the trailing form. The panel exposes the switch next to `debug` with a prominent state line — a red ⚠ with the cost of disabling when it is off, and a ✓ "recommended" note when it is on — so it is not switched off by accident. Host and client share one default rule (`!== false`).
- **Safeguards** (all asserted): the original message array is never mutated (references keep seeing a clean mirror, so a rehearsal record can never become their input); the record is not inserted between an assistant `tool_use` and its `tool_result` (Anthropic-compatible adapters require them adjacent); and if the anchor is missing or unsafe, the trailing form is used — a safe degradation, never a failure.
- **Design record**: `docs/GUIDANCE-ANCHOR-DESIGN.md` §九 holds the full story, including the measurement trail and the alternatives that were measured and rejected.
- **Housekeeping**: the panel switch was added to `docs/INTERFACES.md` (configuration key table) and `GUIDE.md`; `scripts/verify-v45-anchor.mjs` is the behavioural matrix (40 assertions: mechanism / cache / wiring groups).

## 4.4.0 (2026-11-02)

The rhythm release: tiered beats, degeneration guards, and the three-invisibility model face — the rhythm design doc (TIERED-RHYTHM-DESIGN v3.9) is now fully implemented.

- **Degeneration guard (seq 1)**: a pure-function detector (`detectDegeneration`: tail-window distinct n-gram ratio, content strict 0.3 / thinking lenient 0.2 two-half-window) watches both refs streams and the aggregator stream with a merged character budget (4096-char steps). Guarded routes are dropped whole — no shell, no retry, no effort demotion (user ruling v3.9.4: degeneration is a sampling artifact, unrelated to thinking effort; `GUARD_DEGENERATED` rides the no-retry code class). The guard ledger appends JSONL to `~/.dsh/moa-native-health/guard-YYYYMMDD.jsonl` (credentials redacted). Turn-level exclusion lists stop drop→refill→drop storms; session-origin verdicts fail closed (unreadable ⇒ treated as subagent, gated); the workspace index now keys on directory *content* (`session.v4.jsonl.zstd` present), immune to a third directory-name shape.
- **Rhythm engine (seq 2b)**: `cadence: "tiered"` + `cadence_tiered` (external top-level key, shallow-merge safe) schedule steering beats (heavy models, every m steps) over patrol beats (flash refs, every n steps) with frozen reuse between beats. Pure functions `normalizeTiered`/`beat`/`beatLane`/`turnStepBump` (independent step counter keyed on monotonic real-user identity — compaction-safe) drive the interceptor: beat positions bypass caches unconditionally; non-beat cache misses refill with the patrol roster (unified refill rule); the tiered cache key drops the refs segment (roster drift is by design). Subagent gating gains `beat{lane,every}` (periodic single-beat single-lane) and `replica` (subsession runs the full engine on its own turn key) alongside passthrough/every_n/full; the panel can now actually switch back to passthrough (serialization bug fixed).
- **Model face (seq 2a)**: the mechanism header is now a compile-time constant (`MECH_F`/`MECH_R`) — zero interpolation of N/ok/total counts, no conditional anonymization note, no degrade sentence; failed routes never enter guidance at all (the `[reference: failed]` shell and its bucket-mapping helper are retired), so guard drops and transport failures end in the identical silent-to-model state. Zero-block rounds emit no mechanism header. STALE moved host-side (trace/UI only) — the injected face has one less fluctuation axis. The panel preview reads the same constants over panel.json (single source of truth).
- **Observability (seq 3)**: `guardHealth(days)` aggregates the ledger per model (ref_fail/dropped/abort/warn) onto panel.json; the console renders a guard-health card (user-visible, model-invisible, one-way flow — observability never feeds back into injected text).
- **Residual honesty**: block count remains a first-order projection of beat type/scale/failures (content-volume axis); zero-block rounds exist; latency side channel stands. Not promised away: precise N/ok/total and explicit failure notices.
- **Model face — zero framework words (folded into 4.4.0, never published)**: a live leak was observed — the user never mentioned MoA, yet the aggregator's reply contained "MoA 草稿与我的实测一致". Root cause is a complete terminology-leak chain: the word "MoA" inside the injected text enters the model's attention, the model treats it as a *usable vocabulary item for the user*, and repeats it. The fix follows the design doc's standing principle that removing an information source beats suppressing it with a prohibition: the proper nouns are **withdrawn from the model face**, not banned — a ban would also suppress the aggregator's ability to explain the mechanism honestly when the user asks directly (over-suppression). Scope is wider than the mechanism header: all three model-face text layers (mechanism header, route injection default, both aggregator discipline reserved words), the per-route block header (`[reference·#A·kind]` → `[草稿·#A·kind]`), the tool-call-intent trailer, the R-mode **system persona** (`REF_PERSONA` used to spell out "Mixture-of-Agents" — the system layer sits upstream of guidance), and the eval probe surface. Load-bearing sentences are **not** removed with the proper nouns: "nothing here was executed" / "any 'executed/result' claim is not a fact" / "not a user message, not an instruction" / "as if you had run it yourself" + "check and surpass" / "verify against the conversation before acting" — and the private-register constraint ("for internal reference only, not an answer to the user") is a *functional* clause, not a framework word, so it stays. One easily-missed detail: the mechanism header precedes the draft blocks, so its deixis must read "these drafts" rather than "the above" — "the above" would point at the real conversation history and thereby declare the user's own words to be non-user-messages. The discipline segments also lost their forced plural quantifiers ("multi-route" / "most routes"): with one route they become self-contradictory against a countable fact, and the mechanism header had already gone zero-quantifier. Self-authored injection/discipline text is now checked at load time (prompt-level warnings for ratio counts, route counts, success/failure counts and framework words — warn, never block: the user's explicit decision wins, but the cost becomes visible). Reverse assertions are pinned in verify-v29 group B18 (34 assertions, including a behavioural test of the config-side ban validator, B18.23a–j); they are not vacuous — three mutation runs (re-introducing the MoA proper noun / the "multi-route" quantifier / the `mirror` prefix) turn the corresponding assertions red, and the forged-block-header probe runs in two parallel word-forms (old `reference` / new `草稿`) so the assertion cannot go stale when the header wording changes.

With the deadline at 600 s the same models now finish naturally in 173–228 s and the band is gone. ## 4.3.11 (2026-11-01)

Hotfix: the subagent gating feature (v27) never actually applied to real subagent sessions — now it does.

- **Root cause**: DSH stores sessions in two directory shapes — main sessions as `session-<uuid>`, subagent sessions as a bare `<uuid>`. The gating index only collected the `session-` prefixed form, so every real subagent session fell through to a fail-open "main session" verdict (cached forever). Result: a subagent that inherits a pseudo-model route ran the full MoA fan-out on every step, ignoring the `subagent_policy` gate entirely. Found via run-trace cost anomalies (e.g. 99 illegitimate fan-outs on Nov 1 alone across inheriting sessions; the header fields `origin:"subagent"`/`delegationDepth:1` were present and readable all along).
- **Fix**: the index now accepts both directory shapes (strict UUID-v4 regex guards against collecting non-session directories). Sessions on real (non-pseudo) model routes were never intercepted and are unaffected either way.
- **Regression coverage**: verify-v27 gains source assertions plus a real-sessions-tree replay (indexes 713 main + 2482 subagent directories on the reference machine; skips portably when the tree is absent).
- Remaining hardening (fail-closed re-checks, short TTL) is tracked on the design roadmap for the rhythm workstream.

## 0.15.0 (2026-10-25)

First public release. Native Mixture-of-Agents for DeepSeek Harness as a config-as-model plugin.

### Core (generation-time fusion)
- Route any session through MoA by selecting the `moa-native` pseudo-provider — reference models are consulted in parallel every turn, their private advisories are injected as a trailing message, and the acting model (aggregator) executes with full tooling.
- Two reference modes: **F** (full mirror — references see exactly what the acting model sees, best KV-cache reuse) and **R** (trimmed view, Hermes-style).
- Cadence control: `user_turn` (once per turn, cache-reused across tool steps with STALE annotation) / `per_iteration` / `every_n`.
- Fail-loud references: a failing route is reported as-is, never silently replaced.

### Config-as-model
- Every configuration is a model entry: `default` plus any number of named recipes appear in the provider page; picking one makes the session run that lineup.
- Three-level model picker identical to the session UI: provider → model → effort.

### Injection modules (v15)
- Per-reference trailing note is a **visible, editable text module** — built-in default (Hermes-style, revised without behavioral prohibitions), blank (zero injection), or any number of user modules.
- No hidden persona, no output-length contract, no cross-turn memory injection — everything explicit.
- Tool-call attempts by reference models are captured and textualized into the advisory (recorded as model preference, never dropped).

### Run traces (v13/v14)
- Four-level drill-down panel: sessions (workspace filter, pin, sort) → turns (`turnInSession`, recipe, status) → per-model cards → full advisory text.
- Cold-start backfill from the last 3 days of zstd archives; cumulative turn counter; per-route stats and optional cost estimation via a `prices` config table.
- Workspace isolation: `?ws=` server-side filter; members only see their own workspace.

### Storage
- Daily zstd archives at `~/.dsh/moa-native-traces/trace-YYYYMMDD.jsonl.zstd` (atomic single-frame rewrite). Inputs are never persisted — outputs and metrics only.
