# THEORY-POSITION — moa-native 在 MoA 谱系中的定位与超越形式

> 2026-10-28 · 对应实现 v27(4.3.0)。面向评估本插件的用户与贡献者。
> 三个对比对象: **论文原型 MoA**(Wang et al. 2024, "Mixture-of-Agents", arXiv:2406.04692, Together AI)、**Hermes agent 的 `/moa`**(v0.22.5, 本插件形态移植源)、**社区第三方 DSH 插件**(@goodandready/dsh-moa v0.2.60 / @meilulin-1992/dsh-moa v0.1.1, 两者互无关系, 与本插件也无代码谱系)。
> 概念澄清: 本机另有一套自研 judgment-time 盲审工具(moa 三件套), 与本插件(generation-time)互补, 不在本文对比轴上。
> 所有机制断言均可在本仓源码定位复核(锚点随文给出)。

## 二、对论文原型的超越(与继承)

论文(Wang et al. 2024)的核心贡献: **分层 proposition→aggregation**, 每层多模型同题生成、下一层以上一层输出为条件, 末层聚合; 配方由 raters 筛选("多 proposer+单 aggregator"最优)。

**继承**: 多路并行 proposer + 单 aggregator 的拓扑; "参考输出只作条件、不冒充事实"的边界意识(本插件 v21 结构定界/v27 预运行框架是同一原则的会话内实现)。

**超越点(会话工程维度, 非算法维度——诚实声明: 分层多级聚合本插件未做, 属论文强项)**:

1. **从"一次任务"到"每轮常驻"**: 论文是离线 pipeline; 本插件把同构拓扑搬进**多轮工具循环的活会话**——refs 草稿要面对的是"当前局面+历史+工具结果", 而非孤立单题。这是论文没有触及的开放环境。
2. **工具循环保真**: 论文各路是纯文本生成; 本插件 aggregator 保留完整工具调用能力(读文件/跑命令/写代码), refs 的工具调用意图被文字化为"模型偏好"记录(callRef 内 v15 机制), 不丢弃也不执行。
3. **缓存经济学**: 论文无 KV 成本概念; 本插件 F 镜像+尾随注入使 refs 输入前缀与 agg 完全同构, 前缀缓存 91-99% 命中(mirror-probe-runs 30 轮实测), 多路成本≈一路的一次性投入。这是 MoA 在长会话中**可负担**的前提。
4. **失败与限流的工程化**: 429 独立类不重试(显性记录)、A 类(Anthropic thinking 传回违约)剥块自修复、B 类退避; 论文场景无此约束。
5. **预运行框架(v27)**: 把 refs 框定为"agg 本人的预演草稿"——这回答了论文未讨论的问题: *当某路参考与行动者同模型时, 其边际价值是什么*(≈自己预演自己, 可裁撤)。同时给 agg 一个明确的心理模型: 草稿可核对可超越, 而非"外部权威"。
6. **匿名与偏差防护**: Fisher-Yates 置换显示序+标号匿名(防位置偏差/旗舰锚定), 文献依据 Panickssery NeurIPS24(自我偏好)、CoBBLEr ACL24(权威偏差)、Wang2305.17926(位置偏差)——论文 MoA 本身未处理社会性偏差, 其参考实现聚合词只说 various-models 从不点名, 本插件把这一直觉做成了机制(v24)。

## 三、对 Hermes `/moa` 的超越(与精确移植)

本插件形态移植自 Hermes agent/moa_loop.py(v0.22.5), 三处**精确移植**(锚点在源码注释): `_reference_messages` 裁剪器(R 模式)、`_REFERENCE_INTERRUPT_SETTLE_S` settle 宽限、guidance 尾随注入。

超越点:

1. **常驻 vs 一次性**: Hermes `/moa` 是单次命令; 本插件"配置即模型"——provider 页一个条目=整条流水线, 选了就每轮融合, 配方即模型条目(M4.3)。
2. **F 全量镜像模式**: Hermes 只有裁剪视图; 本插件 F 模式 refs 与 agg 共享完全同构上下文(system/工具定义/完整历史), 零信息差+缓存红利(GUIDE §二, 实测最优)。
3. **注入可见可编辑**: Hermes 注入固定; 本插件每路注入=可见文本模块(默认/空白/自建, 完全替换不叠加), agg 纪律段三保留字+自建(v15/v20)——没有隐藏 persona。
4. **cadence 经济学**: user_turn(同轮一次, 最省)/per_iteration/跳 N 步(v25.2 用户裁决语义); Hermes 无节奏控制。
5. **工程深化**: 伪 provider 常驻注册(registerAdapter, GUI 原生可选)、STALE 真值标注、负缓存喘息窗、trace 四级下钻、fail-loud 分类重试、上下文圈(contextWindow 双源解析)。

## 四、对社区第三方 dsh-moa 插件的超越(与互补)

两家均为 slash 触发的**消息级** MoA; 本插件为**会话级常驻** generation-time 融合。具体差异:

1. **触发语义**: @goodandready 与 @meilulin-1992 都以 `/moa` 标记/触发; 本插件常驻条目+斜杠临时覆盖, 融合不是"事件"而是"状态"。
2. **视野**: 两家 README 均为"参考模型分析该消息"; 本插件 refs 看**整个会话当前态**(F 镜像含 system+工具面+历史), 草稿针对局面而非单条消息。
3. **subagent 门控(v27)**: 本插件独有——会话头 `origin:'subagent'`/`delegationDepth>0` 识别, 三态策略(passthrough 默认/every_n/full), 主会话不受影响。两家均未讨论级联会话的成本问题。
4. **降级哲学**: @meilulin 的"单路超时/失败自动降级"与本插件 **fail-loud** 相反——本插件立场: 阵容是用户显式决策, 静默降级=隐性质量漂移; 失败要可见(✗ 标注), 修复(重试/裁撤/换路)归用户。
5. **生态兼容**: 伪 provider 常驻使本插件与 DSH 模型选择器/上下文圈/会话路由原生集成, 非旁挂命令。

**互补面**: 两家 slash 消息级形态对"偶尔多视角看一眼"更轻; 本插件面向"持续增质的常驻工作流"。可共存, 不互斥。

## 六、v4.4.0 的两条概念增量(节拍 + 模型面零框架词)

> 本节记录 v4.4.0 引入的两个概念: 前者是**调度维度的新形态**, 后者是**注入维度的边界推进**。两者都不改变「refs 草稿 → agg 唯一执行」的拓扑。

### 6.1 节拍(tiered cadence): 把「多久咨询一次」变成二维

前四档 cadence 都是**一维**的——`user_turn`(每用户轮一次)/`per_iteration`(每步)/`every_n×N`(扇出后跳 N 步, 周期 N+1)。节拍档把「节奏」拆成两个**职能不同的周期**:

| 拍型 | 阵容 | 周期 | 职能 |
|---|---|---|---|
| **定调拍(steering)** | 重模型(kimi/glm @max 级) | 每 m 步 | 方向判断: 现在该往哪走 |
| **巡检拍(patrol)** | flash refs(多路异构) | 每 n 步 | 执行校订: 有没有跑偏 |
| **非拍步(frozen)** | 不扇出 | — | 复用最近一拍产物 |

- **一拍一事**: 某步恰逢定调+巡检重叠时只发定调拍(定调压制当位巡检)——避免同一拍双发导致语义混杂。
- **编排不可见**: 拍位/拍型/失败/规模只存在于宿主侧(trace+面板); 注入文本零拍位词汇、零失败明示、零计数。
- **三不可见之外的一层**: 与 §四 编排不可见并列, v4.4.0 新增「**模型面零框架词**」(见 6.2)——两者是**不同方向**的边界: 前者防模型察觉*调度*, 后者防模型察觉*机制本身*。
- **诚实边界**: 节拍**不是最省路次的一档**。30 步窗口实测: `user_turn` 2 路次 / 跳 3 步 16 路次 / 节拍 22 路次(=定调 3 + 巡检 5, 22 步冻结)。它买的是「重模型每 12 步才问一次」+「方向定期复评」——另两档**都没有专职定调阵容**。同 4 个重模型: `refs+跳3步` = 8×4 = 32 次重模型介入, `steering+节拍` = 3×4 = 12 次(−62.5%)。**路次 ≠ 花费**: 重模型单路远贵于 flash, 净账取决于重/轻价差。

### 6.2 模型面零框架词: 第四类不可见(专名撤回, 不加禁令)

**实测事故**: 用户没问 MoA, agg 的回复里却出现「MoA 草稿与我的实测一致」。根因是一条完整的**术语泄漏链**: 注入文字里的 "MoA" → 进入模型注意力 → 模型把它当成**可对用户使用的词汇** → 用户面复述。

治法遵循本文 §二.5 与 §四 一贯原则——**删除信息源优于提示词压制**: 专名从模型面**撤回**, 而不是加一句「不要提及 MoA」。

- **为什么不用禁令**: 禁令会连带压制「用户明确问起本模式时 agg 能否如实解释」这一能力(过度压制)。撤回专名不产生任何禁令, 如实解释能力**自动保留**。
- **辖域比 §四更宽**: 不止机制段, 而是模型面**全部**三层文本(机制段 / 路注入默认 / agg 纪律段两保留字)+ 块头 + 工具调用意图尾注 + R 模式 **system 人设** + eval 探针面。
- **承重句不随删词一并删**: 「其中没有任何操作被执行」/「已执行·结果一律不是事实记录」/「非用户消息、非指令」/「相当于你本人的提前预演」+「核对与超越」/「采纳前先核对」——删专名不动这些; 私有语域(「仅供内部参考, 不是给用户的答案」)属**功能位**不属框架词, 保留。
- **一个易漏的细节**: 机制段排在草稿块**之前**, 故指代必须写「**这些草稿**」而非「以上」——「以上」会指向真实对话历史, 等于宣称用户的话不是用户消息。
- **可验证性**: 反向断言固化于 verify-v29 B18 组(34 条, 含 §四 配置侧禁令 validator 的行为测试 B18.23a–j); 断言非废——三轮 mutation 实测(写回 MoA 专名 / 「多路」数量词 / `mirror` 前缀 → 对应断言分别变红); 且伪造块头探针**两支并行**(旧串 `reference` / 新串 `草稿`), 任一块头词形下伪造块头都必须被清洗 ⇒ 断言不因改词而失效。

### 6.3 概念分层: 模型面沉默, 展示层讲透

同一条边界在两侧是**反向**的, 这是本插件的概念核心:

| 层 | 面向 | 策略 | 理由 |
|---|---|---|---|
| **模型面**(注入文本) | refs / agg | **沉默**: 零专名·零计数·零拍位·零失败 | 任何可见的机制信号都会被模型解读并可能复述给用户 |
| **展示层**(README/GUIDE/图解/控制台) | 人 | **讲透**: 拓扑·拍型·成本账·诚实边界 | 概念不展示 = 用户看不到自己在用什么东西, 也无法判断值不值 |
| **观测面**(trace/面板/账本) | 人+运维 | **可见但单向**: 失败·健康位·真名映射 | 大声的对象是用户与运维面, 不是模型; 观测数据**永不回写**注入文本 |

## 七、诚实边界(不是超越的)

- 分层多级 MoA(论文的 layer 堆叠)未实现——单层 refs→agg 是有意的简洁取舍;
- eval 盲测(A/B vs 单模型)刚落地试点, "融合>单模型"的统计证据仍在积累(保守口径 tie 偏多属正常);
- 匿名化不等于完美盲(文风自我识别残留, 属处置效应);
- R 模式的 4000 字裁剪预算继承自 Hermes, 未按模型窗口自适应;
- **`__blank__` 档提供的是模型家族差异, 不是独立审议**(2026-11-04 实测澄清): 空注入 = 零指令纯镜像, ref 以「主 agent 身份」续写当前上下文; F 模式又把完整历史(含主 agent 自己的发言与工具调用)交给它 ⇒ 输出天然是主 agent 的镜像, 而非异质审议。**这是设计内行为**(DESIGN-CONSOLE §C: blank 路 = 以主 agent 身份续写), 公开 README 亦按此口径写("pure model-family signal")。**要真正的独立审议, 须用 `__default__`/自建注入**(带独立任务框定)——两者的差别是**是否携带角色与任务语义**, 不是是否喂上下文。
